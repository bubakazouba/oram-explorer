What this is

A toy-sized but real implementation of two hierarchical Oblivious RAMs, compiled into animation frames. Every logical access you issue runs through the actual data structures: values are stored, moved, found and returned by the simulation, and every read is checked against a plain RAM. The server's view at the bottom is the exact list of physical reads and writes the scheme issued.

How to use it: choose read or write, an address, press Access, then Step or Play. Every few accesses a rebuild happens (the phase banner turns blue); use Next phase to skim it. Turn off Reveal real vs dummy to see only what the server sees: encrypted cells and an address trace with no labels. Try hammering one address, then scanning all of them, and compare the traces: the shape is identical.

OptORAMa (Asharov, Komargodski, Lin, Nayak, Peserico, Shi; Eurocrypt 2020 / JACM)

  • Levels. Level 0 is a 4-slot buffer that is scanned in full. Level l (l ≥ 1) has capacity 4 · 2l-1, up to the largest level of capacity N. Each hashed level is drawn as its bins (one Cuckoo table each), its overflow pile (own Cuckoo table) and its combined stash.
  • Lookup. Scan level 0, then for every non-empty level: scan its combined stash, probe 2 Cuckoo cells of the overflow pile, then 2 Cuckoo cells of bin PRF(addr). After the item is found, every remaining probe is a dummy at random positions. The item is written back to level 0.
  • Rebuild. Every 4 accesses, like a binary counter, levels 0..j-1 merge into the first empty level j (or everything merges into the largest level). Steps: extract each level (copy, tight compaction of unread real items, truncate), intersperse the shuffled arrays, PRF binning in the clear, secret loads, move excess to the overflow pile by tight compaction, per-bin Cuckoo build in the client, write tables, merge stashes.

MegaBlocks (Asharov, Eiluz, Komargodski, Lin; CCS 2025)

  • Asymmetric setting. A server block holds B client words. Each level is a non-recurrent hash table whose bins are single blocks: dynamic packing via PRF(addr) mod C.
  • Lookup. Read level 0's block, then 1 block per level (bin PRF(addr), or a random block once found), each read and written back. Cost: 2 block I/Os per level.
  • Rebuild. Every B accesses. With growth factor g > 2 a level absorbs g-1 merges before spilling into the next, so there are only about log N / log g levels. Steps: gather + pack live words into full blocks, oblivious compaction of blocks, choose a fresh PRF key, pad to half-full bins, butterfly routing (log C rounds, each pairs blocks i and i + 2r and splits words by bit r of their destination), install.

Simplifications (so nothing here misleads)

  • Tiny parameters. N is 8 to 64, bins hold about 4 items, the stash has 3 slots, B is 4 or 8. Real deployments use polylog-sized bins and B in the hundreds; the failure probabilities that the papers bound as negligible are not negligible here.
  • Private retries replace negligible failure. When a toy-sized random choice would fail (secret loads whose excess does not fit the overflow pile, a combined stash overflow, or a butterfly bin overflowing in MegaBlocks), the client silently re-draws that randomness before touching the server. This keeps the server trace data independent, but it peeks at the level's contents in a way the real schemes do not need, and it slightly biases the distributions.
  • PRF. A keyed 32-bit integer hash, not AES. Keys are shown in the client panel as 4 hex digits.
  • Encryption is implied. Every write is a fresh re-encryption in the real schemes; here cells are just shown, or shown as uniform encrypted blobs when Reveal is off.
  • Tight compaction. The paper's linear-time deterministic algorithm (bipartite expander swaps, loose compaction, recursion, packed word tricks) is replaced by 3 rounds of fixed perfect matchings between the front and back halves (expander-like swaps that do real work), followed by a fixed Batcher odd-even merge network on the mark bit that guarantees completion. It is data oblivious and correct, but O(n log2 n), not O(n). It is not order preserving.
  • Intersperse is implemented as in the paper: sample a random bit string, run compaction on it, replay the swaps in reverse on the data. The compaction of the bit string itself is done inside the client here.
  • Level 0 shuffle and per-bin Cuckoo builds happen in client memory. The client reads a whole small bin (or level 0) into private memory and writes back the full fixed-size table. The paper does this with packed word operations and O(1) client memory; the server-visible pattern (read whole bin, write whole table) is the same idea.
  • Cuckoo hashing uses one table per bin with two choices and up to 12 evictions; dummy probes read 2 uniformly random cells. In the paper each level has one combined stash that is merged into a small level; here each level keeps its own combined stash which is scanned on every lookup of that level.
  • Revealed loads. As in the paper, PRF binning in the clear reveals each bin's load. The test suite checks that every access, regardless of address, produces the same number of physical I/Os and the same (read/write, region) sequence; the only exception is how the staging-bin reads split among bins, which is this revealed load vector.
  • MegaBlocks packing pass. Gather + pack streams blocks through a 2-block client buffer and writes exactly one block per block read (full or empty), then compacts blocks. Blocks of the merged levels are counted in physical blocks, as in the paper's I/O metric; word-level work inside the client is free.
  • No de-amortization in either scheme, matching the papers' amortized bounds.

Correctness test

node test.js in the repository runs 200 random reads and writes per configuration (plus a full read-back), checks every returned value against a plain array, verifies the compaction network on random inputs, and runs a second instance with a completely different address sequence (one hot address) and different randomness to confirm identical per-access trace lengths and (op, region) patterns.
